# Design

## Context

main 3ff9d20 没有多模板管理，恢复缓存只有音频/转写/时长；恢复固定走润色，改写引用依赖已消费的全局槽位。feat/sound-feedback 6da365d 含可参考的恢复修复，但同时包含被作者取消的模板库及其他功能，不能整片合并。

已只读核对 Handy 的 transcription_coordinator/actions，沿用 Audie 现有执行编号和缓存归属模式，不引入新的协调器或线程模型。本片在独立 worktree codex/recovery-without-templates 中执行，原分支保持原样。

## Goals / Non-Goals

目标：只迁入三模式恢复与执行隔离，原设置/前端/快捷键/默认提示词不变。非目标：多模板、循环键、提示音、架构拆分、网络取消重写、用户数据或凭据迁移。

## Decisions

- LastTake 增加执行编号、原模式、提示词正文和改写引用，音频继续 Arc 共享；开录使旧执行失效并冻结原三字段中的对应正文，结束/取消时将上下文与音频完整交接。
- 新增一个私有 ActivePromptSlot 包装类型存本次提示词。Tauri 按具体 Rust 类型存 state；不能用与 RewriteSourceSlot 相同底层类型的 type 别名，否则两个槽位冲突。包装只用于区分数据身份，不新增业务层。
- 正常处理和恢复共用 spawn_transcription/finish_pipeline_tail；原文选择、模式处理、历史分类及输出回退沿用原规则；网络完成后、注入前后和终态发布时检查执行有效性。
- ASR 只更新同一执行的缓存，不重建已释放缓存；取消时已有转写仍按原模式记历史。恢复重用转写，连接配置按当时设置读取，正文与改写引用保持快照。
- 缓存交接、状态迁移与清理沿用一把 LastTakeSlot 锁；网络在锁外。六秒清理与主线程真正执行的隐藏操作都检查执行编号；不夸大系统粘贴撤销保证。
- 新恢复测试放 src/tests/recovery/ 按处理行为、缓存/计时及快照分文件，每文件少于 400 行；原 tests 暂不展开全量重组。
- 从 main 出发让模板代码从未进入本片，而不是在用户数据中删除模板字段。其他分支和用户配置不作破坏性操作；架构计划将 templates 功能改回原 text-processing 设置。

## Risks / Trade-offs

- [参考分支混有模板与提示音] → 按函数和行为选择迁入，确认 commands/平台/前端/Cargo 与 main 无差异。
- [状态类型别名冲突] → 使用独立包装并验证快照与改写引用分别保存；不会以两份同类型 state 互相覆盖。
- [取消/定时器竞态] → 保留归属校验，运行迟到成功/失败、注入失败、旧计时器与转写缓存回归，并做负对照确认测试能检出缺陷。
- [无法自动产生真实语音与跨 App 选区操作] → 构建和自动回归完成后明确保留手动项，不将模拟成功写成真机已验收，不开启后续架构切片。

## Migration Plan

先跑 main 基线、补恢复回归，再迁入原修复并适配三份原提示词。运行 Rust 测试、fmt/clippy、前端测试/typecheck/lint/build 与原生构建，更新实际记录。无需配置或数据库迁移；回退只回退本分支切片，不改旧功能分支。
