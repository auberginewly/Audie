# Design

## 已批准范围

沿用作者“都做了吧”的授权连续实施；先调查再修，独立提交后继续下一片，不重复询问已批准范围。使用已有隔离工作区 codex/engineering-followups；基线 8bd115d，保护主工作区与私有文件。

## 实现与职责

1. CI/原生集成由协调者负责：回读 42973172954 的 Windows loader 失败与 macOS cancelled 原因；参考 Tauri/Handy 官方实现，检查 manifest 与 runner 生命周期。修复限必要构建接线，远端验证不以本机编译代替。
2. 诊断隐私：provider 保留错误类别/状态码/固定可操作说明，拒绝不受控 body/URL/原始错误串。前端校验失败只记固定类别和安全计数。允许小而明确的现有层 helper，不建立通用日志框架，不引入库。
3. 工程检查：Node 脚本复用现有 Prettier，检查手写源码/测试物理行数与维护中的公共规范入口；历史进度/证据不借本片全仓格式化。钩子显式安装、幂等，已有用户 hook/config 不覆盖；合并后启用本地。
4. pipeline：仅中文注释与显式 import/use，运行函数正文保持。无新的 state/context/async 模型。

## 验证与系统边界

隐私与工程脚本先失败用例再最小实现，验证 marker 不出现在错误/诊断且错误类别保持；钩子覆盖成功/拒绝覆盖/失败退出码。R/F/native build 与独立两阶段审查后合并；按现有本地合并/推送偏好触发远端 CI 并等待真实结果。

原生验证使用受控临时文本窗口和现有应用；不读取/改写真实 secrets、历史或重置 TCC。先检测可用 UI/Accessibility/Reticle 能力，能执行的真实场景留下证据；需要真人说话或未授权系统访问时说明具体缺口并请求必要输入，其他任务持续推进。没有证据不关闭原 change 手动项。
